# Local release security review

Reviewed the uncommitted implementation against HEAD `e25e210`. No commits, publication or live
launch were made. This report covers the local implementation; it does not certify a public VPS,
hosted provider account or an unavailable external review.

## Confirmed findings fixed

- Existing unverified sessions continued after enabling email verification. Session validation now
  checks the current requirement on every request. A real HTTP document request is refused after
  that change.
- Changing a link password left existing sessions and completed password gates usable. Password
  changes now end non-preview sessions and reset pending gates. Asynchronous password verification
  also rechecks the current hash, preventing an old password from completing during a change.
- Link creation/update could finish after asynchronous hashing with stale room, member or link
  state. The final write rechecks room state, current membership and concurrent link changes.
- Investor actions could retain authorization captured before awaiting request-body parsing. NDA,
  question/reply and request-upload paths now revalidate after reading the body. Raw investor
  uploads recheck current session, NDA and request availability before writing bytes.
- Removed members retained an unexpired investor-preview session. Preview validation now checks
  the member's current existence and removal state.
- Fresh recovery retained references to old-server local rollback snapshots. The staged restored
  database clears that local-only metadata before becoming live; doctor now passes on a fresh host.
- Rollback carried present storage settings but could retain removed S3 settings from the snapshot.
  Carry-forward now replaces that settings namespace exactly. A real rollback after an S3-to-disk
  move verifies the destination stays disk and the documents remain readable.
- API-key name validation allowed 80 characters while the underlying plugin default allowed 32.
  The plugin now uses the declared 80-character limit. Invalid/disabled bearer keys return a
  deliberate unauthorized response rather than escaping through a framework error.
- Outbound IP checks used textual IPv6 patterns. They now use Node's subnet parser, allow ordinary
  public global IPv6 and reject private, mapped, compatible, special-use and transition ranges.
  DNS is checked at connection time, all returned addresses must be public and redirects are refused.
- The host doctor duplicated a failing app status with an unhelpful message. It now returns the
  actual checks, a fix for failures and exit 2 when attention is needed.

- The MCP transport limited the entire JSON envelope to one million bytes, leaving no room for a
  documented 750,000-byte inline file. Its limit now matches the server’s 1 MiB limit; the decoded
  file limit remains 750,000 bytes. The exact boundary and an oversized request were checked.

- Retrying a paused storage move could leave its existing job waiting for the previous backoff.
  Retry now schedules that unlocked job immediately and clears its old error; locked work is not
  duplicated. The real job row and transfer completion were checked.

The fast day-29 test invokes the actual cleanup function with its explicit clock set 29 days ahead,
then restores a real Litestream replica at an actual recorded cutoff. It is controlled retention

exercised; the separate host cycle also rolls back the actual older image.

## Dependencies and review limits

Patched transitive minimatch and esbuild versions remove the moderate advisories. The production
npm audit reports no critical, high or moderate advisories. One upstream low-severity deepmerge
advisory remains, represented by five affected dependency nodes. Its reachable use in this project
is the Svelte Vite plugin merging trusted build configuration, not investor/server request data.
The production server does not run Vite. No patched upstream deepmerge release was available.
See [the advisory](https://github.com/advisories/GHSA-gcqx-w48m-w2h4). Recheck it before publication.

The two-model OpenCode review could not start because no OpenRouter credential was configured.
Neither GLM nor DeepSeek produced a report; this is incomplete external coverage, not a clean
external review. The manual review and real checks above were completed independently of that
runner. Availability records and detailed verification are kept outside the repository in the
local review-reports folder. An independent external security pass remains a launch follow-up.

Public DNS/ACME, a clean live VPS, hosted S3/email credentials, publication and real raise contents
were explicitly deferred by the owner. Keep those separate from local release acceptance.
