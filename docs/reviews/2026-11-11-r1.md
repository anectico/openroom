# R1 implementation and visual review — 11 November 2026

This is a local implementation review, not a production release or an independent security audit.
All database, file and bucket fixtures used here were disposable. Existing user QA data was not
used as a destructive fixture. No commit, push or deployment was made.

## Confirmed changes

Optional S3 now covers encrypted settings, environment adoption, multipart uploads, ranges, zip
and frozen archive reads, and verified migration of retained disk objects. Litestream configuration
uses the bucket, 720-hour retention and CURRENT prefix history. Remote synchronization is checked
through Litestream's socket; health does not infer success from process liveness. Recovery stages
and checks a database before making it live. Installer recovery uses the original secret key and
removes its one-time configuration after checking a credential-free restart.

Investor erasure removes live sessions, activity, private conversations and request uploads,
including session-owned rows without a verified viewer ID. It cancels related work and invalidates
exports. NDA evidence and hashed blocks are preserved, with exceptions documented explicitly.
Stale upload/export/archive completion cannot attach data after erasure. Logo uploads and file
completion recheck room state; storage saves recheck the owner after their remote probe.

## Focused security review

- Owner-only storage operations never return either credential and never put them in audit detail.
  Startup and settings share validation; invalid endpoints fail without echoing credentials.
- Bucket identity is immutable. An existing database pointer cannot be silently adopted by a new
  installation. CURRENT writes are conditional; restored and rolled-back databases use fresh
  prefixes. A wrong key does not change the pointer or create a live database.
- Raw document routes retain current session, link, NDA and permission checks. Restored investor
  file/range requests and erasure of a live session were exercised through HTTP.
- Pending upload completion rechecks session/request state or member/room state after asynchronous
  storage work. Tests also cover a room freezing during logo and file completion and an owner losing
  their role while a storage probe is in flight.
- Schema rollback carries encrypted storage settings and moved object locations, verifies secrets,
  referenced files and database integrity, and retains the replaced database. A persisted prepared
  intent survives a failed reset and resumes on the same new prefix; cancelling it is refused. The host command
  refuses a target image that cannot explicitly confirm S3 support before stopping the current app.
- Existing Markdown sanitization, plain investor text, CSV escaping and outgoing webhook guards
  remain in place. This revision does not claim a new exhaustive audit of every earlier feature.

## Visual findings and revisions

The earlier layout gave equal weight to all destinations, buried file opening in menus, left a
large empty current-viewers region, crowded phone actions and let sharing save controls fall below
the viewport. The revision adds a workspace sidebar, five room destinations plus a settings menu,
direct document navigation, searchable cards/folders, explicit copy actions and a scrolling sharing
form with a fixed footer.

Further screenshot review found clipped investor emails, phone analytics columns outside the
visible table, and a watermark that overwhelmed small PDF pages. Emails now get the full phone row,
analytics put secondary metadata below the email, and the reader uses a compact toolbar with fewer
watermark rows plus a readable identity footer. The question composer is a dialog with a retained
page reference and correct textarea keyboard behavior.

Production-bundle browser checks also passed with no console errors on the overview, sharing editor
and PDF reader.

## Remaining release work

A live hosted S3 account, a slow upload through Caddy, a clean VPS install with HTTPS and external
email delivery have not been validated in this revision. Real raise rooms need the owner's private
content and approved access lists. Day-29 recovery, automatic object cleanup, changing buckets and
moving back to disk remain M6. MCP, generated CLI distribution and the agent skill remain M7.

Erasure does not promise physical deletion from retained backup history or released object bytes.
A restored older backup needs privacy reconciliation before it is reopened to investors.
