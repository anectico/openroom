The baseline was commit `8b226d628b8408f490a17b86cebd140101a67cb3`. Each entry below has a trigger exercised against that revision and a corresponding check against the repaired code. The checks used disposable SQLite databases, local file storage, the real operation registry, production HTTP servers, Chromium and the generated CLI.

## Verification scope

Thirty-four of 37 scenarios failed on the pinned baseline. The three passing controls covered a working CLI request, ZIP access and successful image tracking. All 37 passed after repair. The checks used real raw upload bytes, SQLite foreign-key integrity, PDF text extraction and browser interaction with a changed NDA.

Additional checks covered authenticated admin mutations and audit records, observer denial, a cross-room upload destination, and a local SMTP receiver that accepted one authorized reply and received no further message after blocking the investor. Lint, type checking, catalog consistency, the production build and the Docker image build passed. The final image served its health check and OpenAPI document from a fresh data volume.

File transfers and checksum retries used local storage. The replication check exercised stale status. Live off-server replication and external email delivery were outside these checks.

The optional independent OpenCode reviewers could not start because their OpenRouter credential was unavailable. The findings and verification above come from the local review.
