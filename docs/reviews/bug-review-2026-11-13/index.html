Confirmed findings

1. Question falsely marked sent after access changes

P2 · Confirmed · High confidence

Trigger and consequence. Enable an NDA requirement while an investor has a document question open. The POST follows an access redirect to HTML with HTTP 200; the draft was cleared and Sent displayed although SQLite contained no message.

Fix. Require the question endpoint’s JSON conversation ID before acknowledging success. Keep the draft and explain the access change.

Evidence. Before: sent=1, stored=0, draft gone. After: sent=0, stored=0, full draft retained.

src/routes/v/[linkId]/view/[fileId]/+page.svelte

2. Question draft follows navigation to a different document

P2 · Confirmed · High confidence

Trigger and consequence. Draft a question on Overview, close it, and use Next file. The reused page retained the question while submitting it against Financial model.

Fix. Remount viewer children when the file or investor session changes, resetting file-local UI state.

Evidence. Next document now opens an empty question; PDF resume and successful posting also checked.

src/routes/v/[linkId]/+layout.svelte

3. Reopening a question silently changes its page

P2 · Confirmed · High confidence

Trigger and consequence. Draft on page 1, close the dialog, navigate to page 3, and reopen. The old text was silently relabelled as a page 3 question.

Fix. Preserve the original page while a nonempty draft exists.

Evidence. A real 5,000-character submission was stored once for Overview page 1, after navigating to page 3.

src/routes/v/[linkId]/view/[fileId]/+page.svelte

4. Video shortcuts override native buttons and sliders

P2 · Confirmed · High confidence

Trigger and consequence. Space on Mute started playback instead of toggling mute. ArrowLeft on Volume sought from 7 to 2 seconds.

Fix. Leave native input keys and button activation alone; ignore modified shortcuts.

Evidence. Space muted while paused; ArrowLeft reduced volume from 1 to 0.95 while time stayed at 7; seek slider also worked.

src/lib/viewer/VideoPlayer.svelte

5. Video seek track collapses on small phones

P2 · Confirmed · High confidence

Trigger and consequence. At a 320 px viewport, fixed-width toolbar controls squeezed the seek input to zero width.

Fix. Wrap the toolbar and give the seek slider a full-width row on phones.

Evidence. 320 px screenshot: track width 264 px, no horizontal page overflow. Also checked 390 and 1440 px.

src/lib/viewer/VideoPlayer.svelte

6. Final visible reading interval is lost on tab hide

P2 · Confirmed · High confidence

Trigger and consequence. Visibility changes to hidden before the event handler runs. Checking the new visibility inside account() discarded the interval that had just been read.

Fix. Track the previous visibility, account before changing it, flush on hide, and reset timing on page show.

Evidence. Before: 0 ms. After: 1,587 ms credited. A 1,200 ms hidden interval added nothing; resumed visible time added about 600 ms.

src/lib/viewer/tracker.ts

7. Authentication forms remain disabled after network failure

P2 · Confirmed · High confidence

Trigger and consequence. Disconnect before signing in, setting a password, or changing a password. An unhandled fetch rejection left busy=true and no recovery message.

Fix. Catch failures, clear busy in finally, retain entered values, and handle sign-out failures.

Evidence. All three forms became enabled with an error. Reconnecting completed sign-in, invitation setup and password change without a reload. Sign-out and one-time reset-link consumption checked.

src/routes/admin/login/+page.svelte; routes/admin/invite/[token]/+page.svelte; routes/admin/account/+page.svelte

8. Password-reset HTTP errors report successful delivery

P2 · Confirmed · High confidence

Trigger and consequence. Trigger the real request-password-reset rate limit. The page ignored HTTP 429 and said a reset link had been sent.

Fix. Only show reset success for an OK response; render HTTP and connection failures in the form.

Evidence. Real HTTP 429 now shows Too many attempts, retains the email, and shows no sent confirmation.

src/routes/admin/login/+page.svelte

9. Unchanged NDA is described as changed on repeat entry

P3 · Confirmed · High confidence

Trigger and consequence. Clear the session and reenter after accepting the current NDA. Any earlier acceptance was treated as proof of a new version.

Fix. Read the accepted NDA version ID and compare it with the current version.

Evidence. Same version: no changed warning. Replacement version: warning and HTTP 303 file gate; accepting restores HTTP 200. Unauthenticated file request remains HTTP 401.

src/lib/server/viewer/gates.ts; routes/r/[token]/+page.server.ts

10. Sharing-link edits made during save are discarded

P2 · Confirmed · High confidence

Trigger and consequence. With a slow save request, inputs remained editable after the request body had been captured. A later edit appeared accepted but vanished when the save completed.

Fix. Disable the form fieldset while saving, alongside the existing footer and dismissal guards.

Evidence. Held then continued a real update_link request: input disabled while pending, operation completed normally.

src/lib/admin/LinkEditor.svelte

11. Observer is offered editable retention controls

P3 · Confirmed · High confidence

Trigger and consequence. An observer opening an active room fell into the frozen-room retention branch and saw a form for an operation their role cannot perform.

Fix. Only render retention editing for frozen rooms and a writable member role.

Evidence. Observer retention heading count changed from 1 to 0. Existing server authorization was already enforcing this restriction.

src/routes/admin/rooms/[roomId]/settings/+page.svelte

12. Pending destructive action can appear cancelled

P2 · Confirmed · High confidence

Trigger and consequence. Start freezing a room, then click Cancel while its request is pending. The dialog closed, but the real freeze still completed.

Fix. Disable Cancel and prevent closing the confirmation while busy; guard duplicate starts and submissions.

Evidence. During a delayed real freeze request, Cancel was disabled and Escape kept the dialog visible. Releasing the request froze the disposable room.

src/lib/admin/DangerAction.svelte

13. PDF tools opened from a menu lose return focus

P2 · Confirmed · High confidence

Trigger and consequence. Open Page thumbnails from Reader options, then close tools. Focus was returned to a menu item removed from the DOM, leaving BODY active.

Fix. Capture the stable Reader options trigger when tools are opened from its menu.

Evidence. Before active element BODY; after BUTTON with aria-label Reader options.

src/lib/viewer/PdfViewer.svelte

Counterevidence and test corrections

  • Unverified request uploads did not leak receipts to a later verified session: the upload owner is stored as session-only, and the real verified page showed no receipt.
  • Room settings already remount by room ID, preventing the suspected cross-room draft reuse.
  • Admin authentication failures redirect to sign-in, but the operation helper rejects the non-JSON response rather than reporting success. REST API key failures return HTTP 401.
  • Rapid PDF zoom/render races were not demonstrated and were not changed.
  • Early success checks hit the real three-sign-ins-per-ten-seconds limit; they were rerun outside that window. An early resume check scrolled to the header link, changing the last-read page. The corrected check uses the sticky Back control and waits for dialog dismissal; page 3 resume passes. These harness failures were not counted as product bugs.
