# Configuration

OpenRoom reads its settings from environment variables. On a server installed with `install.sh` they
live in `/opt/openroom/.env`. Only `ADMIN_EMAIL` is required; `install.sh` fills in the rest.

| Variable                       | Default                   | What it does                                                                                            |
| ------------------------------ | ------------------------- | ------------------------------------------------------------------------------------------------------- |
| `ADMIN_EMAIL`                  | required                  | The first owner's email.                                                                                |
| `ADMIN_PASSWORD`               | generated by `install.sh` | The first owner's password, used once to create the owner and then removed from `.env`.                 |
| `OPENROOM_SECRET_KEY`          | generated by `install.sh` | Encrypts saved secrets. Keep a copy: restoring on a new server needs it.                                |
| `OPENROOM_SECRET_KEY_PREVIOUS` | empty                     | Set only while rotating the secret key: the old key. See below.                                         |
| `DOMAIN`                       | `<server-ip>.sslip.io`    | The address OpenRoom answers on. Change it with `openroom-server set-domain`.                           |
| `ACME_EMAIL`                   | the admin email           | The contact email Caddy gives the certificate authority.                                                |
| `OPENROOM_IMAGE`               | the installed release     | The image the server runs. `openroom-server update` and `rollback` change it.                           |
| `OPENROOM_PREVIOUS_IMAGE`      | empty                     | The image before the last update, used by `rollback`.                                                   |
| `RESTORE_FROM`                 | empty                     | Set only during a restore: where the database replica is. `openroom-server restore` sets and clears it. |
| `RESTORE_AT`                   | empty                     | Set only during a restore: restore to this time (ISO 8601) instead of the latest point.                 |

Optional, for people who manage configuration as code. Email is normally set up in the admin pages
(Settings → General and email); when these are set they win, and the admin page shows email as set by
the server.

| Variable                                               | What it does                                                                     |
| ------------------------------------------------------ | -------------------------------------------------------------------------------- |
| `EMAIL_FROM`                                           | The sender, such as `Acme <rooms@acme.com>`. Needed for either provider below.   |
| `RESEND_API_KEY`                                       | Send through Resend.                                                             |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD` | Send through any SMTP server (port 587 by default; 465 uses TLS from the start). |

Set inside the container by the Compose file or the image, not in `.env`:

| Variable                      | Value                  | What it does                                                                                            |
| ----------------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------- |
| `ORIGIN`                      | `https://$DOMAIN`      | The public address. The app uses it for the request origin, so a forged `Host` header never changes it. |
| `ADDRESS_HEADER`, `XFF_DEPTH` | `x-forwarded-for`, `1` | Read the visitor's IP from Caddy.                                                                       |
| `DATA_DIR`                    | `/data`                | The data volume: the database, its replica without S3, snapshots and files on disk.                     |

## Optional S3

Owners normally connect a private bucket in **Settings → Storage & backups**. These environment
variables override saved storage configuration and make it read only in the UI. They also bootstrap
a fresh-server restore before the encrypted settings can be opened.

| Variable               | Default | What it does                                                                           |
| ---------------------- | ------- | -------------------------------------------------------------------------------------- |
| `S3_BUCKET`            | empty   | Dedicated private bucket. Set with both credentials.                                   |
| `S3_ENDPOINT`          | empty   | HTTP or HTTPS S3 endpoint without credentials, query or extra path; empty uses AWS S3. |
| `S3_REGION`            | `auto`  | Provider region; use the actual region for AWS S3.                                     |
| `S3_ACCESS_KEY_ID`     | empty   | Access key ID, encrypted when adopted into settings.                                   |
| `S3_SECRET_ACCESS_KEY` | empty   | Secret access key, encrypted when adopted into settings.                               |
| `S3_FORCE_PATH_STYLE`  | `true`  | Explicit `true` or `false`.                                                            |

Storage configuration is validated the same way in the environment and API. The first startup
persists supplied credentials encrypted so recovery can later remove one-time environment values.
An existing `db/CURRENT` requires restore mode. Once bound, the bucket identity cannot change;
credentials can rotate for that bucket. Use `move_storage` to copy, verify and switch buckets or return to local disk; keep the old bucket for at least 30 days. See [storage and backups](storage-and-backups.md).

`RESTORE_FROM=s3://bucket/db` must match this configuration. `RESTORE_AT` requires an ISO 8601 time
with a timezone. The original `OPENROOM_SECRET_KEY` is required before the first start. The installer
checks restored secrets and files, removes restore and S3 environment values after success, restarts
and checks again. Saved bucket credentials remain encrypted in SQLite; the secret key remains in
`.env`. Never start the old server alongside the restored one.

## Rotating the secret key

`OPENROOM_SECRET_KEY` encrypts the saved secrets: email and S3 keys, link addresses and webhook
signing secrets. It also signs members' sign-in sessions. To change it:

1. In `.env`, move the current value to `OPENROOM_SECRET_KEY_PREVIOUS` and set a new
   `OPENROOM_SECRET_KEY` of at least 32 characters (`openssl rand -hex 32`).
2. Restart (`docker compose up -d`). At start OpenRoom decrypts every saved secret with the old key,
   encrypts it again with the new one, logs how many values it changed and writes a
   `server.key_rotation` entry to the audit log. Every member has to sign in again; API keys and
   investors' sessions keep working.
3. Remove `OPENROOM_SECRET_KEY_PREVIOUS` and keep a copy of the new key somewhere safe. A database
   replica made before the rotation still needs the old key to restore.

If the key does not match the saved secrets and no previous key decrypts them, OpenRoom refuses to
start and says so in the log, so a typo never leaves secrets unreadable.

## Local development

For local development nothing needs setting: `npm run dev` keeps its data in `./data`.

`REPLICA_URL` (the local database replica root, `file:///data/replica` in Docker) and `PORT`,
`HOST` and `BODY_SIZE_LIMIT` are set internally; leave them alone.
